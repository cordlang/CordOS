Architecture · CordOS · x86_64

Cómo funciona CordOS

GRUB entrega el kernel. kmain64 arma memoria, drivers y disco. La sesión pinta login y el escritorio toma el framebuffer — todo en el mismo binario, dueño de la máquina.

EL HILO

kmain64 no vuelve: orquesta y cede

  • GDT / IDT / PIC / PIT, teclado y ratón
  • Syscalls (int 0x80), luego PMM → VMM → heap
  • Framebuffer, splash, PCI / red, AHCI + NosFS
  • Cuentas, splash de producto, scheduler, SMP stub
  • session_run → login → desktop_run

El escritorio es el bucle vivo

Tras un login correcto, gfx_session_run entra en desktop_run: compositor, dock, ventanas, Spotlight (Win/Ctrl + Space). Cerrar sesión vuelve al login; apagar llama a power. Archivos y ajustes escriben NosFS por el VFS, no por un truco de la VM.

Fuera de este dibujo

  • El escritorio corre en ring 0
  • Ring 3 es un smoke test, no las apps
  • SMP: solo el BSP
  • GRUB es andamiaje, no el bootloader final
